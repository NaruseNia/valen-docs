# モジュールと可視性

## パッケージ宣言

すべての `.vln` ファイルは `package` 宣言で始めるのがおすすめです。

```valen
package com.example.app;
```

- Java スタイルのドット区切りパス
- ファイルシステムのディレクトリ階層と一致する必要がある

::: info
パッケージ宣言は**推奨ですが強制ではありません**。パーサーはパッケージ宣言のないファイルを受け付け、リゾルバもエラーを発生させません。テストでは省略されることが多いです。ただし、`internal` 可視性の境界チェックはパッケージパスに依存するため（[可視性](#可視性)を参照）、宣言の省略はアクセス制御に影響します。
:::

## Import 構文

```valen
import java.util.List;                                    // 単一型
import java.util.concurrent.ConcurrentHashMap as CMap;    // エイリアス
```

| 形式 | 例 |
|---|---|
| 単一 import | `import java.util.List;` |
| エイリアス import | `import java.util.HashMap as HMap;` |
| 選択的 import (`{A, B}`) | **サポートされていない** |
| グロブ import (`*`) | **サポートされていない** |

## モジュール

::: warning 未実装
以下に説明するモジュールシステムは**設計済みですがコンパイラには未実装です**。`valenc` CLI に `--module` フラグはなく、Gradle プラグインもまだ存在しません。現在の `internal` 可視性はモジュール ID ではなく**パッケージパスの比較**で制御されています。現在の動作は[可視性](#可視性)を参照してください。
:::

モジュールはビルドターゲット内の**意味的所有単位**です。オーファンルール、`sealed` 許可スコープ、`internal` 可視性を制御します。

モジュールは**ビルドツール駆動**です。Valen ソースに `module` 宣言はありません。

| ビルドモード | モジュール ID |
|---|---|
| Gradle プラグイン | Gradle サブプロジェクト名 = 1 モジュール |
| `valenc` CLI | `valenc --module <name> src/*.vln` (未実装) |

### 設計規則

- 複数のソースファイルが同一モジュールに所属可能（ファイル境界 ≠ モジュール境界）
- 1つのモジュールに複数のパッケージを含められる
- 1つのパッケージが複数のモジュールにまたがることも構文的には合法（非推奨）
- `sealed class` のサブタイプは同一モジュールに存在する必要がある
- オーファンルールのチェックはモジュールレベルで所有権を判定（[Trait](/ja/reference/traits) を参照）

### パッケージとモジュール

| 概念 | 役割 |
|---|---|
| **パッケージ** | ソース階層 + 名前空間 |
| **モジュール** | 可視性、オーファンルール、sealed 許可の所有単位 |

## 可視性

| 修飾子 | スコープ | デフォルト? |
|---|---|---|
| `pub` | どこからでも可視 | いいえ |
| `internal` | 同一パッケージ（現在の実装） | **はい**（デフォルト） |
| `private` | 宣言プライベート（クラス本体内またはトップレベルファイル内） | いいえ |

可視性修飾子が指定されない場合、`internal` がデフォルトです。

### 現在の `internal` 実装

モジュールシステムが未実装のため、`internal` 可視性は**パッケージパスの比較**で判定されます。

```
check_visibility_from_package():
  def_package == accessor_package → 許可
  いずれかが None → 拒否
  パッケージが異なる → 拒否
```

- 同一パッケージのファイルは互いの `internal` メンバーにアクセス可能
- 異なるパッケージのファイルはアクセス不可
- パッケージ宣言のないファイル同士は互いのメンバーにアクセス可能（両方 `None`）

::: info 将来
モジュールシステムが実装されると、`internal` のスコープはパッケージパスからモジュール ID に変更されます。
:::

```valen
pub fn api() -> String { "public" }
internal fn helper() -> String { "same package" }   // 修飾子なしと同じ
private fn secret() -> String { "this file only" }
```

## スコープ演算子

| 演算子 | 用途 | 例 |
|---|---|---|
| `::` | Enum バリアント、関連関数 | `Shape::Circle(r = 5.0)`, `User::from_name("Alice")` |
| `.` | パッケージパス、型パス、値メンバー | `java.util.HashMap`, `user.name` |

### 用語

Valen では以下の3つの用語のみを使います。

| 用語 | 意味 |
|---|---|
| **メソッド** | `self` レシーバを持ち、値に対して呼び出す |
| **関連関数** | `self` なし、クラス本体で定義、`Type::name()` で呼び出す |
| **enum バリアント** | enum のバリアント |

`static` という用語は Valen の仕様では**使いません**（連携コンテキストで Java の `static` に言及する場合を除く）。
